# Add an algorithm

An algorithm for computing approximations is a subtype of [`ApproximationAlgorithm`](@ref)
with its options as fields, and a method of [`_fit`](@ref) that approximates
convex data by a convex piecewise affine function. Everything else is provided
by the package: concave data is approximated by negating the values, non-convex
data as a difference of convex functions with `DC()`, functions are sampled over
a bounding box, and the data is checked before the algorithm is called.

As an example, the following algorithm takes the tangent planes of the data at
a few points, which is a convex approximation that lies below convex data.

```@example tangents
using PiecewiseAffineApprox

struct Tangents <: PiecewiseAffineApprox.ApproximationAlgorithm
    planes::Int
end

function PiecewiseAffineApprox._fit(a::Tangents, data::FunctionEvaluations{1})
    o = sortperm(first.(data.points))
    idx = round.(Int, range(1, length(o); length = a.planes + 2))[2:(end - 1)]
    planes = map(idx) do i
        l, r = o[max(i - 1, 1)], o[min(i + 1, length(o))]
        slope = (data.values[r] - data.values[l]) / (data.points[r][1] - data.points[l][1])
        Plane((slope,), data.values[o[i]] - slope * data.points[o[i]][1])
    end
    return PWAFunc{Convex,1}(planes)
end

PiecewiseAffineApprox.supported_dimensions(::Tangents) = 1:1

x = range(-1, 1; length = 20)
approx(FunctionEvaluations(x, x .^ 2), Convex(), Tangents(3))
```

The same algorithm now works for concave data, for non-convex data as a
difference of convex functions, and for sampling a function:

```@example tangents
approx(FunctionEvaluations(x, -x .^ 2), Concave(), Tangents(3))
approx(sin, [(0, 2π)], DC(), Tangents(3))
```

## Options

The rest of the package reads the options of an algorithm through the trait
functions [`planes`](@ref), [`concave_planes`](@ref), [`metric`](@ref),
[`strict`](@ref) and [`optimizer`](@ref). Their defaults return the fields of
the same name, so an algorithm that follows the naming needs no methods, and
one that stores its options differently implements the functions instead.
Options are changed with [`with`](@ref), which by default calls the keyword
constructor, as generated by `@kwdef`. The number of planes of the concave part
of a difference of convex approximation is `concave_planes`, by default equal
to `planes`.

Algorithms can wrap other algorithms through these functions: [`Select`](@ref)
chooses the number of planes for any algorithm with a `planes` option by
fitting with `with(inner; planes = p)` for each candidate `p`,
[`Restart`](@ref) runs an algorithm with an `rng` option from several random
starts and keeps the best, and [`Alternating`](@ref) fits the two parts of a
difference of convex approximation with different algorithms.

Two more functions describe what the algorithm accepts:
[`supported_dimensions`](@ref) for the numbers of variables, used above to
restrict `Tangents` to one variable, and [`requires_convex_data`](@ref) for
algorithms that need data that can be interpolated by a convex function. Such
algorithms are used on the parts of a decomposition of non-convex data, but
not to refit them.

## Conventions

- Validate the options in `_fit` and throw an `ArgumentError` for unsupported
  values; `PiecewiseAffineApprox._check_option` gives a uniform message.
- An option `metric` takes the values `:l1`, `:l2` (with `:rms` as an alias)
  or `:max`, and `strict` the values `:none`, `:outer` for an approximation
  below the data and `:inner` for one above it.
- Measure errors with [`approximation_error`](@ref).
- Use `rng` for randomness, and advance it so that repeated calls give
  reproducible, different results, as [`Cluster`](@ref) does.
- The tests in `test/test_algorithms.jl` run every algorithm of the package
  through the same cases; add a new algorithm to that list.
